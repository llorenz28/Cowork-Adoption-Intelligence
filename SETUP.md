# Set up Cowork Adoption Intelligence

The current template reads deterministic entity CSVs generated by the validated
Python preprocessor. Use the fabricated sample first, then choose either a
protected manual refresh or the Power Automate and Azure Container Apps path.

## Before you start

For a local sample or manual refresh:

- Windows
- Current [Power BI Desktop](https://powerbi.microsoft.com/desktop/)
- Python 3.11 or later
- Separate protected input and output folders

For production, identify:

- an authorized Purview or PAX collection owner
- optional Microsoft 365 usage, HR, and identity data owners
- a Power BI owner who will validate, label, publish, and operate refresh

Read [Security roles and access](docs/SECURITY_ROLES.md) and
[SECURITY.md](SECURITY.md) before requesting permissions or handling customer
data.

## Path A: validate with fabricated data

### 1. Download and extract

Download:

1. [`Cowork-Adoption-Intelligence-Automation-v0.1.0.zip`](release/Cowork-Adoption-Intelligence-Automation-v0.1.0.zip)
2. [`Cowork-Adoption-Intelligence-Sample-Data.zip`](release/Cowork-Adoption-Intelligence-Sample-Data.zip)
3. [`Cowork Adoption V3.pbit`](Cowork%20Adoption%20V3.pbit)

Extract the automation bundle to `C:\CoworkAdoptionRelease` and the sample to
`C:\CoworkAdoptionSample`. The sample folder should contain:

```text
C:\CoworkAdoptionSample\
  _VERIFY.txt
  cowork_users.csv
  CoworkConsumptionDetails.csv
  CoworkUserDetails.csv
  CoworkUserOrgDetails.csv
  purview_audit\
    CoworkAudit-Synthetic-Part01.csv
    CoworkAudit-Synthetic-Part02.csv
```

All sample people are fictional. Identities use `@example.com`, and resource URLs
use `tenant.example.com`.

### 2. Generate the entity files

```powershell
python C:\CoworkAdoptionRelease\container\Cowork_Purview_Preprocessor_v0.1.0.py `
  --input C:\CoworkAdoptionSample `
  --output C:\CoworkAdoptionPreprocessed
```

The input and output folders must be separate and non-overlapping. The processor
stages and validates all output before replacing a destination that it previously
created.

### 3. Run both validators

```powershell
python C:\CoworkAdoptionRelease\container\Cowork_Purview_Preprocessor_v0.1.0.py `
  --validate-output C:\CoworkAdoptionPreprocessed

python C:\CoworkAdoptionRelease\container\Validate-CoworkCompatibility.py `
  --output C:\CoworkAdoptionPreprocessed
```

The output must contain `manifest.json` and exactly 13 `entity-*.csv` files. Both
commands must report success before Power BI refresh begins.

The packaged sample baseline is:

| Check | Expected |
| --- | ---: |
| Cowork audit rows | 3,342 |
| Cowork thread tasks | 900 |
| Active users | 72 |
| Prompts | 2,225 |
| Entity files | 13 |

### 4. Open the template

1. Open `Cowork Adoption V3.pbit`.
2. Set `PreprocessedOutputPath` to `C:\CoworkAdoptionPreprocessed`.
3. Select **Load**.
4. If prompted, use the local-file privacy level approved by your organization.
5. Wait for all model queries and visuals to finish.
6. Confirm all nine pages render without visual errors.
7. Confirm **Adoption Metric Guide** is populated.
8. Confirm the status bar shows the **Public** sensitivity label.

## Path B: manual production refresh

### 1. Create protected folders

Keep production files outside the cloned repository:

```text
C:\CoworkAdoptionData\
  purview_audit\
    Purview-Cowork-2026-08-01-to-2026-08-31.csv
  CoworkUserDetails.csv
  CoworkConsumptionDetails.csv
  CoworkUserOrgDetails.csv
  identity\
    cowork_users.csv
```

Preserve immutable raw exports separately. Use only protected working copies for
normalization. Record the source owner, reporting window, export time, and every
transformation.

### 2. Prepare the required Purview source

The required source is a Purview Audit Search CSV containing
`CopilotInteraction` records. Its outer columns must include:

```csv
RecordId,CreationDate,Operation,UserId,AuditData
```

At least one valid row must contain
`CopilotEventData.AppHost = cowork`, case-insensitively, inside `AuditData`.
Preserve the JSON payload. Do not expand, reformat, or manually repair it.

Large reporting periods can be split into non-overlapping CSV exports under
`purview_audit`. The processor discovers sources recursively and deduplicates
immutable record identities.

Microsoft references:

- [Audit permissions](https://learn.microsoft.com/purview/audit-get-started#step-2-assign-permissions-to-search-the-audit-log)
- [Audit search](https://learn.microsoft.com/purview/audit-search)
- [Audit export limits](https://learn.microsoft.com/purview/audit-log-export-records)
- [Copilot audit fields](https://learn.microsoft.com/purview/audit-copilot)

### 3. Add optional sources

Keep one current schema-valid file for each optional source.

| Source | Preferred filename | Required headers |
| --- | --- | --- |
| Cowork usage | `CoworkUserDetails.csv` | `UserPrincipalName,DisplayName,TotalTasks,ScheduledTasks,UserInitiatedTasks,ActiveDays,LastActivityDate` |
| Organization | `CoworkUserOrgDetails.csv` | `userPrincipalName,displayName,department,jobTitle,jobFamily,city,country,costCenter,manager,businessUnit` |
| Identity | `cowork_users.csv` | `id,displayName,userPrincipalName` |
| Consumption | `CoworkConsumptionDetails.csv` | Use the version-matched contract in `container/cowork-contract.json` |

Use lowercase UPNs consistently. Optional-source joins are case-sensitive.
Microsoft 365 usage reports can conceal user identities; do not weaken tenant
privacy settings or grant broad administrator roles solely for this report.

### 4. Process and validate

```powershell
python C:\CoworkAdoptionRelease\container\Cowork_Purview_Preprocessor_v0.1.0.py `
  --input C:\CoworkAdoptionData `
  --output C:\CoworkAdoptionPreprocessed

python C:\CoworkAdoptionRelease\container\Cowork_Purview_Preprocessor_v0.1.0.py `
  --validate-output C:\CoworkAdoptionPreprocessed

python C:\CoworkAdoptionRelease\container\Validate-CoworkCompatibility.py `
  --output C:\CoworkAdoptionPreprocessed
```

Any required-header, malformed-JSON, duplicate-collision, manifest, entity, or
compatibility failure must stop the refresh.

### 5. Load and reconcile

1. Open the Public PBIT.
2. Set `PreprocessedOutputPath` to the validated output folder.
3. Load and refresh.
4. Reconcile source and report counts for the same time window.
5. Check organization joins and optional usage totals.
6. Review every page for unexpected identifiers or values.
7. Review the editable controls on **Capacity Assumptions**.
8. Read [INTERPRETATION_GUIDE.md](INTERPRETATION_GUIDE.md) before presenting
   maturity, enablement-partner, assisted-time, or capacity results.

## Path C: scheduled Power Automate refresh

Use this path for controlled recurring collection and refresh. Power Automate
starts and monitors one Azure Container Apps Job; it does not process audit rows.

### Prerequisites

- Azure Container Registry
- Azure Container Apps environment
- Azure Storage account with Azure Files
- user-assigned managed identity for the job
- Power BI workspace and semantic-model IDs
- gateway host that can read the Azure Files UNC path
- Power Automate premium access for HTTP with Microsoft Entra ID

The job identity needs the exact PAX and Azure permissions documented in
[`automation/README.md`](automation/README.md). Use the least-privilege custom
role in `automation/deploy/CoworkJobStarterRole.json` for the Power Automate ARM
connection.

### 1. Deploy the job

Sign in with Azure CLI, then run:

```powershell
.\automation\deploy\Deploy-CoworkAcaJob.ps1 `
  -SubscriptionId '<subscription-guid>' `
  -ResourceGroup '<container-apps-resource-group>' `
  -EnvironmentName '<container-apps-environment>' `
  -AcrName '<registry-name>' `
  -ManagedIdentityResourceId '<managed-identity-resource-id>' `
  -ManagedIdentityClientId '<managed-identity-client-id>' `
  -TenantId '<tenant-guid>' `
  -StorageAccountName '<storage-account-name>' `
  -StorageAccountResourceGroup '<storage-resource-group>' `
  -InitialStartUtc '2026-01-01T00:00:00Z'
```

The mounted share uses this durable contract:

```text
active/
  purview_audit/CoworkPurviewAudit.csv
  CoworkUserDetails.csv
  CoworkConsumptionDetails.csv
  CoworkUserOrgDetails.csv
  identity/cowork_users.csv
preprocessed/
  manifest.json
  entity-*.csv
state/
status/
logs/
metrics/
```

The watermark advances only after collection, preprocessing, structural
validation, and compatibility validation succeed.

### 2. Build the cloud flow

Follow
[`automation/power-automate/BUILD.md`](automation/power-automate/BUILD.md)
exactly. Create a solution-aware flow with:

- recurrence trigger concurrency set to one
- HTTP with Microsoft Entra ID connection to Azure Resource Manager
- Power BI connection for refresh and refresh history
- environment variables for subscription, resource group, job, workspace, and
  semantic-model IDs
- generic notifications that contain no audit, user, path, manifest, or tenant
  details

`CoworkRefreshOrchestrator.logic.json` is an implementation map, not an
importable Power Automate solution package.

### 3. Connect Power BI

Set `PreprocessedOutputPath` to:

```text
\\<storage-account>.file.core.windows.net\<file-share>\preprocessed
```

Configure the on-premises data gateway with a service identity that has read
access to the share. Power BI reads the validated entities; it does not execute
Python or PAX.

### 4. Acceptance test

1. Keep the recurrence disabled.
2. Complete any required initial backfill manually.
3. Confirm `status/latest.json` reports success.
4. Confirm `preprocessed/manifest.json` uses format
   `cowork-python-preprocessor-manifest-v1`.
5. Run the flow manually and confirm it tracks the exact ACA execution.
6. Confirm Power BI refresh starts only after job success.
7. Force a safe failure in a nonproduction deployment and confirm Power BI does
   not refresh.
8. Enable the production schedule only after the backfill is caught up.

## Publish safely

1. Keep raw and generated files outside Git.
2. Treat entity files and manifests as customer data.
3. Confirm the report shows the sensitivity label required by policy.
4. Restrict Power BI workspace access and sharing.
5. Configure retention for raw, generated, log, and status data.
6. Document the reporting window, source coverage, assumptions, and exceptions.

The release PBIT is labeled **Public** because it contains no imported customer
data. A refreshed customer report must be relabeled according to organizational
policy before sharing.

## Troubleshooting

| Symptom | Action |
| --- | --- |
| Python is not recognized | Install Python 3.11+, reopen PowerShell, and run `python --version` |
| No Purview source is discovered | Confirm a CSV contains the required outer audit headers |
| Malformed `AuditData` JSON | Re-export the affected batch; the processor intentionally stops |
| Existing output is rejected | Use a new path or inspect the foreign folder; the processor will not overwrite it |
| Compatibility validator fails | Do not refresh Power BI; resolve the entity, AppHost, ThreadId, or reconciliation failure |
| Folder error during load | Confirm `PreprocessedOutputPath` points to the validated output |
| Optional source is ignored | Use one preferred filename with exact headers |
| Organization visuals are blank | Check UPN case and overlap |
| Service refresh cannot reach files | Configure and map the gateway connection |
| Flow times out or reports failure | Review protected ACA Job logs and Power BI refresh history; do not expose payloads in notifications |
